# design-sync notes — @kaiord/workout-spa-editor

Repo-specific gotchas for syncing this design system to claude.ai/design.
Read this before running the sync; append to it whenever something new bites.

## Shape and entry

- **Shape is `storybook`.** Config dir is `packages/workout-spa-editor/.storybook`
  (NOT at the repo root — the monorepo keeps it in the SPA package).
- **The package is an app, not a library.** It is `private`, has no
  `main`/`module`/`exports`, and its `dist/` is a vite app build (`index.html`
  plus hashed chunks) that exports nothing. The converter needs a module whose
  named exports become `window.KaiordDesignSystem.*`, so
  `.design-sync/gen-entry.mjs` synthesizes one at
  `packages/workout-spa-editor/design-system.ts` (committed, regenerated by
  `buildCmd`). **Re-run it whenever components are added or renamed** — a
  component missing from the barrel is missing from every synced design.
  - It emits explicit named re-exports, not `export * from`. With ~85 component
    modules, star re-exports make same-named symbols ambiguous, and ESM resolves
    an ambiguous star export to `undefined` at runtime instead of failing at
    build time.
  - `src/components/pages/` is deliberately excluded: those are router-wired app
    screens, not reusable design-system parts.
- **`cfg.tsconfig` is required.** Components import via the `@/*` path alias
  (`tsconfig.app.json` → `./src/*`); without the tsconfig the converter's esbuild
  cannot resolve them.
- Build workspace deps first: `pnpm -F "@kaiord/workout-spa-editor^..." build`.
  The `^...` selector builds the siblings (`@kaiord/core`, `ai`, `fit`, `i18n`, …)
  without rebuilding the SPA app itself, which the sync does not need.

## Storybook was broken before this sync (two fixes, both committed)

Nothing runs `storybook build` in CI, so both had gone unnoticed since the
TypeScript 7 migration. `pnpm storybook` / `pnpm build-storybook` failed outright.

1. **`.storybook/main.ts` was not valid ESM.** The package is `"type": "module"`,
   so the config loads as ESM, where the bare `require` that `getAbsolutePath`
   called is not defined. Every build died with
   `SB_CORE-SERVER_0002 (CriticalPresetLoadError)`. Fixed with
   `createRequire(import.meta.url)`, preserving the helper's original intent.
2. **`reactDocgen: "react-docgen-typescript"` crashes on TypeScript 7.**
   `@joshwooding/vite-plugin-react-docgen-typescript` drives the TS compiler host
   directly and throws `Cannot read properties of undefined (reading 'fileExists')`
   against `typescript@7.0.2`. Switched to the babel-based `"react-docgen"`, which
   is TS-version-independent. Autodocs prop tables still render; only the
   extraction mechanism changed.

**Failure signature to recognize:** `storybook build` exits **0** while printing
`Storybook exited with an error`. `index.json` can be written by a run whose vite
build then failed — always check `iframe.html` exists and is >10KB before trusting
the reference.

## The design system is coupled to Vite

Three separate blockers, all the same shape: the components only build under
Vite, because nothing had ever bundled them with anything else. None is a bug in
the app — each is correct _inside Vite_ — but together they are the reason a
first sync is not a one-command job. All three fixes live in `.design-sync/` and
regenerate via `buildCmd`; **no app source was changed for any of them**.

- **`import.meta.glob` (Vite-only) in `src/i18n/resources.ts`.** esbuild emits
  IIFE, where `import.meta` is `{}`, so the module threw
  `import_meta.glob is not a function` at load — and since nearly every component
  translates, that took down **all 35 previews** (0/35 rendering). Replaced for
  the bundle only by `gen-i18n-resources.mjs`, redirected via the `./resources`
  entry in `tsconfig.paths.json`.
- **The real CSS only exists after Vite/postcss runs.** esbuild picked up just
  2.1 KB of uplot chart CSS from a side-effect import — and because that is over
  the converter's 500-byte "is this a placeholder?" threshold, its
  storybook-CSS scrape never fired and everything would have shipped unstyled
  while looking fine in the log. `build-css.mjs` runs the repo's own postcss
  config to produce the 117 KB stylesheet.
- **Inter is referenced by absolute host paths** (`/fonts/…`, `/editor/fonts/…`)
  that only resolve while the SPA is being served. Stripped from the compiled CSS
  and re-declared once in `.design-sync/inter.css` via `cfg.extraFonts`. This one
  is invisible to the preview-vs-storybook comparison — both panels fall back to
  the same default — so it has to be closed deliberately.

## Converter gotchas worth knowing

- **`cfg.tsconfig` cannot point at `tsconfig.app.json`.** The converter's
  `tsconfigPathsPlugin` strips comments with a string-unaware regex, so the `/*`
  inside the alias key `"@/*"` opens a phantom comment, `JSON.parse` throws, and
  a silent `catch` disables path resolution with no diagnostic — surfacing much
  later as `Could not resolve "@/utils/logger"`. `.design-sync/tsconfig.paths.json`
  is comment-free for exactly this reason: **do not add comments to it.**
- **Path fields have different bounds.** `cfg.entry` is cwd-relative;
  `cfg.tsconfig` and `cfg.extraFonts` are package-relative but bounded to the
  repo; **`cfg.cssEntry` is bounded to the package** and is silently skipped
  (`! cssEntry: … resolves outside the package`) if it escapes. That is why the
  compiled stylesheet is written to `packages/workout-spa-editor/.design-sync-styles.css`.
- **The package needs `"types"` in its `package.json`.** The converter derives
  the legal component set from the package's type entry; without one it found 0
  exports and dropped all 35 storybook components as `[TITLE_UNMAPPED]`, which
  reads like a naming problem and is not one.
- **Story-local contexts need `cfg.storyImports.shim`.** Imports that resolve to
  an internal context compile _from source_ into the preview, creating a second
  React context instance that the bundled component cannot see — the component
  then throws its own "must be used within a Provider" error even though the
  story's decorator wrapped it correctly. `shim: ["/src/contexts/", "/src/i18n/"]`
  forces them onto the bundle global so identity is shared.

## Storybook has no global providers (why 3 components ship floor cards)

`.storybook/preview.ts` sets backgrounds and controls but mounts **no providers** —
no theme, no locale, no units. Any component reading `useTranslate`/`useTheme`
therefore renders in Storybook only if its own story remembers to wrap it, and
most do not. Consequences:

- Every story of **WorkoutStats** (6), **WorkoutList** (4) and **MainLayout** (4)
  fails in the repo's own Storybook (`sb-error` — "no storybook root content"),
  verified with the compare harness after confirming the harness renders Button,
  Icon, StepCard and ThemeToggle correctly. They are skipped via
  `cfg.overrides.<Name>.skip` and ship the honest floor card. **They are still
  fully functional in the bundle** with types and docs — only the preview card is
  unauthored, because there is no reference render to verify one against.
- `MainLayout` additionally requires a real `PersistencePort`. Supplying one would
  pull the Dexie persistence stack into the design tool; not worth it for a card.
- The sync's own previews DO mount a provider chain (`cfg.provider`:
  Theme → Locale → Units → GarminBridge), which is what fixed `PushButton`. So
  previews can render strictly more than Storybook does.
- **Worth fixing upstream:** adding those providers as global decorators in
  `.storybook/preview.ts` would repair the repo's Storybook and let all three
  components get real preview cards on the next sync. Deliberately not done here —
  it changes Storybook for everyone, which is a repo decision, not a sync one.

## How to grade these previews (method, not defects)

The two panels of a compare sheet are **not at the same scale**, and the
difference is not uniform: the storybook shot is a tight crop of the component
(96x96 for a 64px AvatarRing) while the preview shot is the full 900x700 page,
and the sheet shrinks both to fit its columns. The preview therefore always looks
smaller, and every block-level component looks wider.

- **Grade geometry from the raw PNGs**, not the sheet: crop to non-background
  pixels and compare the content bounding box. Across the card batch every
  component's content HEIGHT was pixel-identical and only the WIDTH differed —
  that is the signature of "framing only". Eyeballing the sheet produces false
  `mismatch`/`close` grades.
- **Grade colour from the raw shots too.** Input's label looked bluish in
  storybook and grey in the preview on the shrunk sheet; at full resolution the
  slate label, border, placeholder and helper colours are identical.
- **`parameters.layout: "centered"` shrink-wraps the story container**, so text
  that wraps in storybook does not wrap in the full-width preview (Metric's
  "1h 12m", SummaryStrip's `WithRouteAndHeart`). Cause is container width, not
  styling. Grade `match`; do NOT add a width wrapper to an owned `.tsx` to force
  the wrap — that fabricates a layout the story never specifies.
- **Inter is genuinely shipping on both sides**, so typography comparisons are
  like-for-like rather than a matching pair of fallbacks: the reference resolves
  it through the first `@font-face` in `sb-reference/assets/iframe-*.css`
  (relative path, file present) while the second rule's absolute
  `/editor/fonts/...` dead-ends; the bundle ships `fonts/` from `cfg.extraFonts`.

## Known render warns (triaged — a warn NOT listed here is new)

- **`[RENDER_THIN]` AiBanner "variants render identically" — legitimate.** All
  three stories are a closed Radix accordion by design (the story's own doc
  comments say so). The variants differ only in `useAiRuntimeStore` state, which
  has no visual effect while collapsed; storybook renders them identically too.
- **`[RENDER_THIN]` BottomNav "variants render identically" — triaged, still open.**
  The nav DOES render now (`viewport: "390x700"`), but the three stories capture
  byte-identically because the active tab comes from wouter's `useLocation` and
  the story's `Router` decorator lands in a second copy of wouter. See the
  per-component finding below; the knob is `cfg.extraEntries` +
  `cfg.storyImports.shim` for `wouter`. **This is the top action for the next
  sync.**
- **`[REFERENCE_STALE?]` on scoped compare runs.** Fires when the bundle changed
  but `sb-reference` did not. Check whether any DS _source_ moved
  (`git status -- packages/workout-spa-editor/src styles/`): converter-input
  changes (`.design-sync/**`, the generated barrel) move the bundle without
  moving the design, and the reference stays valid. Rebuild the reference only
  when component source or stylesheets actually changed.

## Per-component findings from the verification campaign

- **`SaveErrorDialog` is clipped by a harness bug, not by this repo.** Its root is
  `position: fixed; inset-0` rendered in place (it does not portal). The card page
  styles the story wrapper with `transform: translateZ(0)`, which makes that
  wrapper the containing block for `fixed` — and its in-flow height is 0 because
  its only child IS the overlay. So `inset-0` collapses to a ~32px band and the
  dialog's header sits above y=0. `ConfirmationModal`, a Radix dialog, is NOT
  affected precisely because it portals to `document.body`, outside the
  transformed wrapper — which isolates the cause. Not fixable from config or from
  a preview `.tsx` without fabricating layout; reported upstream.
- **`BottomNav` rendered nothing on EITHER side.** Its root is `md:hidden` and the
  capture viewport is >=768px, so the nav was `display:none` in storybook and in
  the preview — the `[RENDER_THIN]` "variants identical" warn meant "nothing
  rendered", not "variants collapsed". Fixed with
  `cfg.overrides.BottomNav.viewport: "390x700"`. **Watch this one**: it is the
  failure mode where a component looks verified and was never actually seen.
- **`ZoneDist` is blank on the REFERENCE side, not the preview.** Its root is
  `flex gap-[2px]` with no width and children styled only `flex: <value>` (grow,
  0 basis), so under `layout: "centered"` storybook shrink-wraps it to width 0
  (all four sb shots are the same white image, identical MD5). The preview mounts
  it in a block context and paints correctly. Graded on the component's own
  render per the rubric's gating clause. NOT a general `layout: "centered"`
  problem — ZoneMap uses it and renders fine because it has intrinsic text width.
- **`ErrorMessage` needs an owned preview** (`.design-sync/previews/ErrorMessage.tsx`),
  and the cause is generic: storybook's actions addon turns
  `argTypes.<prop>.action` into an IMPLICIT arg, injecting a spy handler into
  every story of the meta even when that story's own `args` never mention it. The
  generated wrapper's `compose()` merges only `meta.args` + `story.args`, so those
  handler props stayed undefined and the component hid its action buttons. The
  owned preview synthesises `args[k] = () => undefined` for every
  `at[k].action !== undefined` whose arg is undefined. **Delete this file if the
  generator ever handles the actions addon** — owned previews are never
  machine-deleted and would shadow the fix. `SectionHead` declares `onAction` the
  same way and happens to render identically only because its visible label is a
  separate prop.
- **The actions-addon gap was swept across the whole roster — `ErrorMessage` is
  the only component it can affect.** Eight others declare handlers the same way
  (`Button.onClick`, `ConfirmationModal.onConfirm/onCancel`,
  `DurationPicker.onChange`, `RepetitionBlockCard.onEditRepeatCount/onAddStep/
onUngroup/onDelete`, `SaveErrorDialog.onClose/onRetry`, `SectionHead.onAction`,
  `StepCard.onSelect`, `StepEditor.onSave/onCancel`), but none gates visible UI
  on the handler being defined. The single conditional render among them,
  `SectionHead`, keys off `action !== undefined` — the label prop — and merely
  wires `onAction` to the resulting button's `onClick`. This matters because
  `[STORY_CAP]` means a defect could hide in an uncaptured tail story; the sweep
  covers the source, not just the captured stories. **Re-run the sweep when a new
  story adds `argTypes: { onX: { action: ... } }`:**
  `grep -rl "action:" --include="*.stories.tsx" src/components` then check the
  component for `onX &&` / `onX ?` conditional rendering.
- Skipped as `sb-error` (they do not render in the repo's own storybook):
  `PushButton` ×3 (needs `GarminBridgeProvider`), `ConfirmationModal` ×6 (Radix
  portals outside `#storybook-root`, so the reference measures an empty root — the
  component is fine; only `Interactive`, the closed state, is gradeable),
  `ZoneDist` Zone1Only, `StepEditor` No Step (returns null with no step).

## Re-sync risks (what to watch next time)

- **`gen-entry.mjs` and `gen-i18n-resources.mjs` must be re-run when components,
  contexts or locale files are added or renamed** — `buildCmd` does it, but a bare
  `package-build.mjs` run does not. A component missing from the barrel is
  missing from every synced design, silently.
- **`.design-sync/tsconfig.paths.json` must stay comment-free** (the converter's
  parser breaks on `/*` inside strings — see above). Adding a comment there
  silently disables `@/*` resolution.
- **`cfg.provider` is part of the grade contract.** It was set mid-campaign and
  cleared all existing grades; the four solo components were re-verified
  afterwards and showed no regression, but any future provider change invalidates
  every grade again.
- **`[STORY_CAP]` tails were never individually graded.** `TargetPicker` captured
  6 of 17 (HeartRate zone/%max/range, Pace, Cadence, OpenTarget, WithError,
  Disabled uncaptured) and `ConfirmationModal` 6 of 8 — real variant coverage
  worth `--max-stories 17` on a later pass. `Button` 6/14, `Input` 6/18,
  `StepCard` 6/19, `Badge` 6/15, `Icon` 6/11 likewise.
- **Sibling-trusted verdicts** were used per the rubric's sampling rule for
  components whose primary story graded `match` and which were warning-free.
- The build was produced on node v24.15.0 with the converter's own playwright
  (chromium 1243), not the repo's pinned 1.62.1.

## Toolchain

- `.nvmrc` pins node 22, but only v24.15.0 was installed locally; `engines.node`
  is `>=22.12.0`, which v24 satisfies. The build was produced on **v24.15.0**.
- The repo pins `@playwright/test@1.62.1` → chromium **1234**, which was not in
  the local playwright cache (1223/1228 were). The converter installs its own
  playwright under `.ds-sync/` and downloaded chromium **1243**; it does not use
  the repo's pin. Nothing to reconcile — the two are independent.
