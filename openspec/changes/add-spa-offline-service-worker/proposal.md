## Why

`kaiord.com/app/` installs as an app (#1566), but the installed app is
useless without a connection. Every chunk loads from the network, so a cold
start in a gym basement or on a plane shows the browser's offline page. The
editor itself needs no network: workouts, the library and the calendar all
live in IndexedDB.

#1566 left the service worker out on purpose. A worker that caches the shell
can leave an installed client running an `index.html` whose chunks the host
no longer serves. This change adds offline support together with the update
strategy that #1566 said it would need.

## What Changes

- A hand-written service worker, `app/sw.js`, scoped to `/app/`. It precaches
  the whole hashed build of one deploy (every JS and CSS chunk, the font, the
  icons, the manifest and the shell). It serves those cache-first, answers a
  navigation inside the scope with the cached shell, and does not intercept
  anything else: version.json, cross-origin requests (analytics, AI
  providers), and anything outside `/app/`.
- The precache manifest is generated by a deploy-time script. It runs over
  `merged-dist/app` after the last step that rewrites `app/index.html`, so the
  revision recorded for the shell is the hash of the bytes Pages actually
  serves.
- Registration runs only in production builds (`import.meta.env.PROD`), with
  scope `import.meta.env.BASE_URL`. The dev server never has a service worker.
- Updates never reload on their own. When a new worker is waiting, a toast
  says "New version available · Reload" (en/es). Clicking it activates the
  worker and reloads that tab only. The previous version's cache survives one
  update, so other open tabs keep working until they reload.
- A kill switch: a repository variable makes the deploy emit a
  self-destructing `sw.js` that clears the caches and unregisters. Documented
  in a new runbook.
- A dist guard and a Chromium e2e over the Pages-like server. Every other e2e
  runs with `serviceWorkers: "block"`.

## Capabilities

### New Capabilities

- `spa-offline`: the editor's service worker, covering precache, update
  prompt, scope, kill switch and guards.

### Modified Capabilities

- `branding`: the installable manifest requirement drops its clause that
  forbids a service worker.

## Impact

- **Packages.** `@kaiord/workout-spa-editor` (private): the worker source, the
  registration and the update toast, en/es strings, and Playwright config.
  Repo tooling: one generator script and one dist guard, each with
  `node:test`.
- **CI/deploy.** `deploy-site.yml` gains a "Generate SPA service worker" step
  after "Inject SPA route fallback", plus the guard. The CI `build` job's site
  guards run the guard over a locally assembled tree.
- **Dependencies.** None added.
- **Users.** Installed and returning visitors download the build once per
  deploy (about 1.1 MB gzipped) in the background.
