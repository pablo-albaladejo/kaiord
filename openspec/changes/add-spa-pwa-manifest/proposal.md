## Why

Chrome on Android says "This app cannot be installed" for `kaiord.com/app/`.
The SPA's `index.html` links no web app manifest, so the browser has no name,
start URL, scope or icons to install it with. Kaiord is local-first and
calendar-centric; athletes open it daily from a phone, and an installed app
opens straight to the calendar in its own window.

## What Changes

- **Manifest.** `packages/workout-spa-editor/public/manifest.webmanifest`,
  copied verbatim by Vite:
  - `id`, `start_url` and `scope` are all `/app/`, the path the deploy
    serves the SPA from (`deploy-site.yml` copies the SPA dist to
    `merged-dist/app/`).
  - `display: "standalone"`, `name` and `short_name` "Kaiord".
  - `theme_color` and `background_color` are `#0d0d0d`, the value of the
    `<meta name="theme-color">` already in `index.html`.
  - Icons: 192 and 512 PNG (`purpose: "any"`) and one 512 PNG with
    `purpose: "maskable"`. Their `src` is relative to the manifest, so they
    resolve under `/app/` whatever the build base.
- **Icons.** Generated by `pnpm brand:images` (`scripts/build-brand-images.mjs`),
  the script that already renders `apple-touch-icon.png`.
  - The `any` icons render from `assets/mark-app-icon.svg`, the
    apple-touch master.
  - The maskable icon renders from a new master,
    `assets/mark-app-icon-maskable.svg`. It has a full-bleed background and
    the mark scaled inside the central 80% safe zone, because the OS crops
    maskable icons to its own shape.
  - The script mirrors the three PNGs into the SPA's `public/`, and the
    existing mirror test keeps them byte-identical to their masters.
- **Link.** `index.html` gets `<link rel="manifest" href="/manifest.webmanifest">`.
  Vite prefixes public-asset URLs in `index.html` with `base`, so the
  production build (`VITE_BASE_PATH=/app/`) emits `/app/manifest.webmanifest`.
- **Guard.** A dist test reads the built SPA and asserts that:
  - the HTML links the manifest at `<base>manifest.webmanifest`;
  - the manifest parses, with `id`, `start_url` and `scope` all `/app/` and
    `display` `standalone`;
  - the 192 and 512 icons exist with those pixel dimensions, plus one
    maskable 512.

  It skips unless `REQUIRE_SPA_DIST=1`, like the docs dist guards. CI's
  `build` job runs it over the SPA build. The deploy runs it over
  `merged-dist/app` with base `/app/`, the tree that actually ships.

### Decision: no service worker, no offline

This change adds no service worker and no offline cache. Chrome no longer
requires a service worker for installability, and the manifest alone clears
the "cannot be installed" error.

A service worker would cache the app shell and its hashed chunks. A deploy
then leaves installed clients running a stale `index.html` that points at
chunks Pages no longer serves, which is the failed-lazy-import failure the SPA
already has to recover from. Offline support, if it ever comes, needs its own
change with an update strategy.

## Impact

- **Packages.** `@kaiord/workout-spa-editor` (private): `public/` and
  `index.html`. Repo tooling: `scripts/build-brand-images.mjs` and its test,
  plus one new master in `assets/`.
- **CI.**
  - `ci.yml` `build` job: the SPA dist guard runs next to the site guards.
  - `deploy-site.yml`: the same guard runs over the merged `/app/` tree.
- **Hosting.** GitHub Pages serves `.webmanifest` as
  `application/manifest+json`, the type browsers expect. No server config is
  needed.
- **Specs.** `branding` (ADDED requirement).
